# Taiwan Bilingual Hub — School Yellow-Pages Rollout — Continuation Prompt

I'm building simple one-page bilingual "yellow pages" introductions for Taiwanese public schools (and universities) that don't have their own bilingual website. This continues work from a previous session — pick up execution directly, no need to re-plan from scratch.

## Site & repo
- Site: `taiwan-bilingual.org`, repo at `~/Documents/Claude/repos/taiwan-bilingual` (local static site, push to `main` to deploy via GitHub Pages)
- `/schools/<county-slug>/index.html` is each county's directory page, listing every school/university with a status badge
- `/schools/<school-slug>/index.html` is each individual profile page

- `schools/magong-hs/index.html` — pattern for when the county directory has a WRONG school name (build under the real name, keep the wrong name only as the dict key when updating badges later)

**Page rules** (all pages, no exceptions found so far):
- No speaker/emoji button next to the school name in hero
- Sections in order: hero (English/Chinese name, township/district, tagline EN+ZH, quick facts: Founded/Grades/Type/Location, badge) → About (EN+ZH paragraphs) → Highlights (3-4 **synthesized** cards with emoji+title+say-span+ZH subtitle+description — never raw-dump the FACTS bullet list) → Local Culture → Visit (address, Google Maps link, official-site link, source note)
- Visit section links the school's own official (Chinese, or English if confirmed real) website, labeled `School's Official Website (Chinese) ↗`
- No "Full Site" badge ever on these pages (that's a different tier for fully custom bilingual builds)
- No photos/images anywhere — pure text
- Footer always: "Last updated: July 2026" + "Content adapted and condensed from the school's official Chinese-language website by the Taiwan Bilingual Hub team, not yet reviewed by the school. If you're from [School Name] and would like to correct or expand this page, please contact us." with `mailto:luke@mycultureconnect.org`
- Breadcrumb matches whatever `/counties/<slug>/` link pattern the county's own index.html already uses — check that file first
- Region CSS class (`cty-band cc-XXX`) must match whatever the county's own index.html already uses (`cc-north`/`cc-central`/`cc-south`/`cc-east`) — always check, don't assume by geography (e.g. outlying islands like Kinmen/Matsu/Penghu all use `cc-central`, not the unused `cc-island` class that exists in the CSS but is applied nowhere)
- Founding years predating/coinciding with Japanese rule (1896–1944ish): show Western year + "(Japanese colonial era)" rather than forcing an awkward ROC conversion
- Unknown founding years: omit that quick-fact gracefully, never fabricate a date
- Don't fabricate ANY fact — "unknown"/"none found" is always fine

## The workflow that's been working well
1. **Check the county's current state**: `grep -o 'badge badge-[a-z]*"' schools/<county>/index.html | sort | uniq -c` and `grep -n 'cty-band cc-' schools/<county>/index.html`. Most counties are still 100% "Coming soon" (no pre-populated URLs) — same ground-up situation as Changhua/Kinmen/etc. (Only Miaoli and Chiayi County already have the lighter "badge-official" tier — direct links to schools' own sites — pre-applied; that's a different, smaller task if you tackle those two.)
2. **Extract the full school list** by reading the index.html directly (township/district, Chinese name, level tag). Watch for: schools listed twice under both JH+ES or JH+SH tags (combined schools — treat as ONE institution/page, but the badge-update script needs to convert BOTH rows to the same slug).
3. **Split into 3-4 research batches** of ~10-17 schools each by geography, to keep parallel agents balanced. Launch them all in one message (parallel `Agent` tool calls). Each research agent prompt should:
   - Ask it to find the official URL (since usually none exist yet), founding year (ROC+Western), 2-4 facts, 1 culture-connection sentence, address
   - **Explicitly tell it not to spawn sub-agents** ("do this yourself directly using WebFetch/WebSearch, do NOT delegate") — this avoids rate-limit cascades from a past-session failure mode
   - If a research agent errors mid-response (API connection closed, returns no real data) — just relaunch that one batch, telling it to keep the response more concise so it completes
   - Save each batch's returned findings to `/tmp/<county-name>/researched_batch_X.txt` yourself (the agent's final text IS the data, copy it into a file with Bash heredoc)
4. **Before generating pages, check slug collisions** against the whole repo: `for slug in ...; do if [ -d "schools/$slug" ]; then echo COLLISION; fi; done` (note: this shell has a recurring bug where large `for X in $VAR` loops sometimes silently fail to iterate — if that happens, fall back to `ls schools/ | grep -E "^(a|b|c)$"` instead). Many generic Chinese names (中正國小, 中山國小, 成功國小, etc.) recur across counties — prefix with a county code (e.g. `kl-zhongzheng-es` for Keelung, `ph-zhongzheng-es` for Penghu) when a collision is found.
5. **Launch parallel page-generation agents**, one per research batch. Each prompt should:
   - Point at the template + 1-2 relevant example pages (including special-case examples above if this batch has a university/closed-school/combined-school)
   - Give the exact slug/Chinese-name/level/URL list, and the county's `cc-` class + breadcrumb pattern
   - Point at the batch's `/tmp/.../researched_batch_X.txt` file
   - Restate all the page rules above
   - **Require self-verification**: "after creating all N files, run `ls -la schools/<slug>/index.html` for EACH slug individually and confirm non-trivial size (~9000+ bytes) before reporting done" — a past batch silently skipped 2 files without this check
   - Tell it not to run git commands (file creation only) and not to spawn sub-agents
6. **After each generation batch completes**: verify file count/existence, spot-check 1-2 pages (especially any special cases), preview one in browser if convenient, then `git add` the batch's directories + commit + push. Don't wait for all batches — push incrementally per batch group like prior counties did.
7. **Update the county index badges** with a Python regex script (see any prior `/tmp/<county>/update_badges.py` for the exact pattern — they're all nearly identical): build a `name_to_slug` dict, regex-match `<div class="srow srow-empty" data-level="X">...badge-soon...` blocks by exact Chinese name, replace with `<a class="srow" href="/schools/<slug>/">...badge-yp...`. Handle the university row separately (its `nm` div has an embedded English name + `<span class="zh">`, different regex). Handle duplicate-name combined schools by just re-running the same replace (matches both occurrences). Run it, confirm `matched == total_rows` and `unmatched == []`, confirm only the CSS class-definition line still contains "badge-soon" (not an actual row), then commit+push.
8. **Verify in browser** via the Preview tools: navigate to the county page, run `document.querySelectorAll('.badge-yp').length` vs `.badge-soon`, confirm 100%/0 respectively.

## Scale/pacing notes
- A county of ~50-65 schools takes about 4 research batches + 4 generation batches, each batch taking several minutes — plan for a long session with `ScheduleWakeup` between dispatches (900-1500s works well) rather than polling.
- Always launch the parallel batches together in one message (multiple `Agent` tool calls) to actually run concurrently.
- Watch context usage — if it's getting long mid-county, that's fine, just keep going batch by batch; the work is naturally checkpointed by git commits, so you can always resume cleanly from wherever the last push landed.
